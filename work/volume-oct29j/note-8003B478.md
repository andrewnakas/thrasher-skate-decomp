## What was fixed

`extern u8 D_8008234C[]` plus `(REC *)` casts made gcc anchor the record pointer at `+0x6C`, turning
every field store into a negative displacement (`sh $s1,-0x68($a0)`). Declaring the object as
`extern REC_8003B478 D_8008234C[]` — a native record array, the way the merged sibling types its
object — removed the anchoring and cut the residue from 65 to 32 differing words. The body then
compiled to the exact target size, and the `lhu`/`sll`/`or` packing of the two globals and both
`%gp_rel` stores matched on their own.

## Where the streams first diverge

- **`0x8003B48C`** — game `slti $a3,$s0,0x101`; ours `lui $v0,%hi(D_8008234C)`. The game computes the
  loop-invariant `slti`/`addiu 1`/`addiu 0x100` *before* it materialises the base address; gcc emits
  them after it. Ordering, not content: the three words exist on both sides.
- **`0x8003B4D0`** — game `sh $s1,0x4($a0)`; ours `sh $s1,-0x68($a0)`. gcc biases the induction
  pointer by `+0x6C` (the last field's offset) so the loop's stores become negative displacements.

## Shapes measured, all 32 of 71 differing

`REC *` walk with `rec++`; `u8 *` walk with a per-iteration cast; an `s32` address walker with explicit
offsets; `first`/`start`/`end` derived from the symbol instead of from the walker; a signed cast on the
compare. `/* cflags: -fno-strength-reduce */` is **worse** here — **6 of 71 matching, size 0x118 vs
0x11c** (two words short) — so the flag's documented positive rule (single scalar pointer induction
variables) does not extend to this body, and it should not be spent on it again.

## Does a merged unit prove the missing shape?

Yes for the offsets, no for the compare. 21 merged units emit a positive-displacement pointer walk with
a fixed increment; the smallest is `func_80016D00`, whose source is `do { *d++ = *s++; } while (s != end);`
and whose stream keeps `sw … 4(v1)`, `8(v1)`, `12(v1)` then `addiu v1,v1,16`. So positive displacements
are reachable here. But **every one of those 21 walks uses an equality test**, while `func_8003B478`'s
loop tail is `slt $v0,$a0,$t0` + `bnez` — a signed less-than. No merged unit demonstrates a signed
pointer compare with positive displacements, so the loop tail remains unproven and the body stays
parked at **39 of 71** rather than hunted further.
